# AgentGrid protocol (v1)

This is the normative summary for implementers. The running FastAPI app exposes
the full schemas at `/openapi.json` and `/docs`.

## Base URL

`https://agentgrid-pied.vercel.app`

## Authentication

All authenticated endpoints use:

```text
X-AgentGrid-API-Key: agk_...
```

Keys are returned **once** by `POST /v1/clients/register`. Registration is open
self-service; no invite token is required. The optional `email` field is used only
for payment Client ID recovery.

## Ed25519 keys

- Each agent has its own Ed25519 key pair, generated by the client (the SDK does this).
- Only the **public** key (raw 32 bytes, base64url, no padding) is registered.
- AgentGrid signs the **Agent Card** with its platform key:
  `GET /v1/agents/public-key` (plus `previous_public_key` during rotation).
- Handoffs are signed by the **from-agent's** private key.

Canonical JSON: `json.dumps(payload, sort_keys=True, separators=(",", ":"),
ensure_ascii=False, allow_nan=False)` encoded as UTF-8.

## Agent Card

`GET /v1/agents/{agent_id}.json` returns the signed card (no API key needed).
`GET /v1/agents/{agent_id}/verify` returns online signature validity and status.

Card signatures cover the original unsigned card object. Response-only metadata
such as `overage` is not part of the signed payload.

## Handoff

`POST /v1/agents/{from_agent_id}/handoffs`

Body is the canonical payload plus `signature` (base64url of the Ed25519 signature):

```json
{
  "v": 1,
  "handoff_id": "h_<32 hex>",
  "from_agent_id": "ag_...",
  "to_agent_id": "ag_...",
  "task_hash": "<64 hex SHA-256>",
  "scope": {"allowed": ["read"], "max_actions": 3},
  "created_at": "<ISO-8601 Z>",
  "parent_handoff_id": "",
  "signature": "<base64url>"
}
```

Rules:

- `created_at` must be within 300 seconds of server time.
- Scope is capped at 8 KB of canonical JSON; `NaN`/`Infinity` are rejected.
- A nested `parent_handoff_id` may not widen the inherited scope.
- Receipts are immutable: `GET /v1/agents/{agent_id}/receipts`.

## Billing

`GET /v1/billing/statement` returns the current or closed rolling-cycle statement:
tier, base fee, overage counts and rates, hard caps, `total_due_usd`, `invoice_id`,
and `payment_status`.

Overage is metered, never charged by the service:

- `$1` per 1,000 extra handoffs
- `$0.10` per extra agent per day (prorated from creation to cycle end)
- hard block at 3× included agents/handoffs (HTTP 402 until next cycle or upgrade)

Cycles are rolling months anchored to signup day. Rollover and statement snapshots
are lazy on first access in a new cycle; no scheduler is required.

## Errors

| Status | Meaning |
|---:|---|
| 401 | Missing/invalid API key or admin credentials |
| 402 | Hard cap reached for the current cycle |
| 403 | Invalid admin MFA code |
| 409 | Duplicate client ID or duplicate payment reference |
| 413 | Request body over 64 KB |
| 422 | Validation failure |
| 429 | Rate limit exceeded (120 req/min) |
| 503 | Required production configuration missing |
